# Operation Scenarios - ระบบหุ่นยนต์ส่งอาหาร

เอกสารนี้อธิบายตำแหน่งอ้างอิง เส้นทาง และการควบคุมภารกิจผ่าน POS/Kiosk และ Keypad ของหุ่นยนต์รุ่นปัจจุบัน ระบบไม่มี IR sensor, LCD แยก หรือปุ่ม Manual Override

## 1. ผังร้านอาหารและพิกัด

~~~text
+--------------------------------------------------+
|                                  +----------+    |
|                                  | Table 1  |    |
|                                  +----+-----+    |
|                                       |          |
|  +------------+                 Junction        |
|  |  Kitchen   |====================+             |
|  |  Station   |                 +--+-------+     |
|  +------------+                 | Table 2  |     |
|                                 +----------+     |
+--------------------------------------------------+
~~~

กำหนด Serve Station เป็นจุดกำเนิด <code>(0, 0)</code> และทิศเริ่มต้นเป็นแกน <code>+X</code> ค่าเริ่มต้นใน <code>config.py</code> คือ Junction <code>(2.0, 0)</code>, Table 1 <code>(2.0, +0.6)</code> และ Table 2 <code>(2.0, -0.6)</code> เมตร ปรับ <code>JUNCTION_X</code>, <code>TABLE1_Y</code> และ <code>TABLE2_Y</code> ให้ตรงพื้นที่ก่อนใช้งาน

| จุด | พิกัดเริ่มต้น | ความหมาย |
| --- | --- | --- |
| Serve Station | <code>(0, 0)</code> | จุดวางอาหารและจุดกลับ |
| Junction | <code>(JUNCTION_X, 0)</code> | ทางแยกไปยังโต๊ะ |
| Table 1 | <code>(JUNCTION_X, +TABLE1_Y)</code> | โต๊ะด้านซ้ายของทางเดิน |
| Table 2 | <code>(JUNCTION_X, -TABLE2_Y)</code> | โต๊ะด้านขวาของทางเดิน |

ระบบหลักใช้ waypoint จากตำแหน่ง encoder odometry และ LiDAR safety guard หยุดความเร็วเมื่อพบสิ่งกีดขวางด้านหน้า เส้นทางที่ใช้เป็นลำดับ waypoint ไม่ใช่ global planner สำหรับหลบสิ่งกีดขวาง

## 2. ตั้งภารกิจที่ครัว

POS/Kiosk บนจอสัมผัสเป็นช่องทางหลัก Keypad 4x4 ใช้ควบคุม POS draft ชุดเดียวกันและดูคำแนะนำ/สถานะบนจอได้

| การทำงาน | POS/Kiosk | Keypad |
| --- | --- | --- |
| เลือกชั้น 1 หรือ 2 | แตะบัตรชั้น | <code>A</code> เลือกชั้น 2, <code>B</code> เลือกชั้น 1 |
| กำหนดโต๊ะ | แตะโต๊ะ 1 หรือ 2 | <code>1</code> หรือ <code>2</code> |
| ยืนยัน/เปลี่ยนสถานะอาหารที่วางแล้ว | แตะปุ่มยืนยัน | <code>C</code> |
| ล้างรายการของชั้นที่เลือก | แตะล้างชั้น | <code>D</code> |
| ล้างรายการทั้งหมด | แตะล้างรายการ | <code>*</code> |
| เริ่มส่ง | แตะเริ่มภารกิจ | <code>#</code> |

พนักงานวางอาหารด้วยตนเอง; ไม่มี sensor ตรวจว่ามีอาหารอยู่บนชั้นจริง ภารกิจจะรับเฉพาะรายการที่มีปลายทางและสถานะอาหารพร้อมแล้ว การกำหนดโต๊ะใหม่ใน POS Server ปัจจุบันตั้งสถานะอาหารเป็นยืนยันแล้ว ส่วน <code>C</code> ใช้สลับสถานะ จึงควรตรวจสถานะบนจอก่อนเริ่ม

## 3. Scenario 1: ส่งอาหารโต๊ะเดียว

1. ที่ครัว เลือกชั้นและโต๊ะจาก POS หรือ Keypad
2. วางอาหารบนชั้นนั้นและตรวจว่ารายการบน POS แสดงสถานะพร้อมส่ง; ใช้ <code>C</code> สลับสถานะหากต้องแก้ไข
3. เริ่มภารกิจบนหน้าจอหรือกด <code>#</code>
4. หุ่นยนต์เดินทางจากครัวไป Junction แล้วต่อไปยังโต๊ะเป้าหมาย
5. เมื่อถึงโต๊ะ ระบบรอการยืนยันรับอาหารบน POS หรือกด <code>#</code>
6. หลังยืนยัน ระบบกลับครัวและแสดงสถานะภารกิจบน POS/Kiosk

~~~mermaid
sequenceDiagram
    actor Staff as พนักงาน
    participant POS as POS/Kiosk และ Keypad
    participant FSM as Delivery FSM
    participant Motion as Waypoint Controller
    participant Robot as Arduino / มอเตอร์
    actor Customer as ลูกค้า

    Staff->>POS: เลือกชั้นและโต๊ะ
    Staff->>POS: ยืนยันอาหารที่วางแล้ว
    Staff->>POS: เริ่มภารกิจ
    POS->>FSM: ส่งรายการงาน
    FSM->>Motion: ส่ง waypoint ไป Junction และโต๊ะ
    Motion->>Robot: ส่งคำสั่งความเร็วผ่าน ROS/Serial
    Robot-->>Motion: ส่ง Encoder feedback
    Motion-->>FSM: รายงานถึงโต๊ะ
    FSM-->>POS: แสดงว่ารอรับอาหาร
    Customer->>POS: ยืนยันบนจอ หรือพนักงานกด # ที่ Keypad
    POS->>FSM: ยืนยันรับอาหาร
    FSM->>Motion: กลับ Serve Station
~~~

## 4. Scenario 2: ส่งอาหารสองชั้นสองโต๊ะ

ที่ครัวกำหนดปลายทางให้ทั้งสองชั้นและยืนยันอาหารที่วางแล้ว จากนั้นเริ่มภารกิจครั้งเดียว ระบบเรียงรายการตามหมายเลขชั้นจากน้อยไปมาก ส่งโต๊ะแรก รอการยืนยันรับอาหาร แล้วเดินทางไปยังโต๊ะถัดไป เมื่อยืนยันรายการสุดท้ายแล้วจึงกลับ Serve Station

~~~mermaid
stateDiagram-v2
    [*] --> AtKitchen
    AtKitchen --> ToTable1: เริ่มภารกิจที่มีสองรายการ
    ToTable1 --> WaitPickup1: ถึงโต๊ะแรก
    WaitPickup1 --> ToTable2: ยืนยันรับอาหาร
    ToTable2 --> WaitPickup2: ถึงโต๊ะถัดไป
    WaitPickup2 --> ReturnKitchen: ยืนยันรับอาหาร
    ReturnKitchen --> AtKitchen: กลับถึงจุดเริ่ม
~~~

## 5. สิ่งกีดขวางและข้อผิดพลาด

| เหตุการณ์ | การทำงานของระบบ |
| --- | --- |
| LiDAR ตรวจพบสิ่งกีดขวางในเขตด้านหน้า | Waypoint controller หยุดส่งความเร็วเดินหน้าและรอจนทางโล่งก่อนทำงานต่อ |
| ยกเลิกภารกิจจาก POS ขณะหุ่นยนต์กำลังทำงาน | POS ส่งคำขอหยุดและแสดงสถานะกำลังยกเลิก |
| การนำทางหรือการกลับสถานีล้มเหลว | FSM เข้าสถานะ <code>ERROR</code> และหยุดหุ่นยนต์; กู้คืนผ่าน POS หรือกด <code>*</code> บน Keypad |
| รอรับอาหารที่โต๊ะ | ยืนยันผ่าน POS/Kiosk หรือกด <code>#</code> บน Keypad; ไม่มีการตรวจจับการหยิบอาหารอัตโนมัติ |

## 6. การแสดงผลและสถานะการเคลื่อนที่

| สถานการณ์ | Odometry / มอเตอร์ | LED Matrix 32x8 |
| --- | --- | --- |
| เดินตรง | Encoder odometry และ PID ควบคุมความเร็วล้อ | ไม่มีการแสดงสถานะเดินหน้าจาก firmware ปัจจุบัน |
| เลี้ยว | ควบคุมล้อซ้าย/ขวาให้หมุนตามเป้าหมาย | แสดงแอนิเมชันลูกศรซ้ายหรือขวาตามคำสั่งจาก Pi |
| หยุดเมื่อถึง waypoint หรือพบสิ่งกีดขวาง | ปิด/ลดคำสั่งความเร็วตามสถานะ controller | ไม่มีไฟเบรกเฉพาะ |
